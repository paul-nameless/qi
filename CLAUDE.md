# qi

Minimal Go coding agent for the terminal.

## Layout
- `main.go` only `var version` (stamped by goreleaser's `-X main.version`) and `os.Exit(app.Main(os.Args[1:], version))`
- `internal/app` everything else, exporting only `Main`: `cli.go` the flags on a `flag.FlagSet`, usage, `-version`, `-show`, `-check-config`, exit codes; `version.go` the stamped version, else one from build info; `run.go` config, provider and agent wiring shared by both modes (`buildAgent`: the agent's only tool is `run` wrapping the functions, `newProvider`, `resolveConfig`, `loadHooks`, `submitPrompt`), `headless.go` `-q`/stdin mode (`-json` tees every session entry to stdout via `session.CreateOptions.Tee`, the same bytes as the file), `repl.go` interactive loop, `commands.go` slash commands and image attachment, `cost.go` `/cost` (sums the `usage` of this session file and of the subagent files whose meta names it as `parent_session`; compaction entries carry their summary request's usage, and `usage` entries record billed requests that left no message: rejected replies, failed summaries, abandoned retry attempts), `settings.go` the `/config` toggles (`run_code`, `show_reasoning`, `terminal_images`: applied live and saved with `config.SetValue`, into the active profile when it sets the key; the builtin picker stays open and switches in place), `picker.go` the pickers (`"builtin"`, the default, is `ui.Editor.Pick`; any other value runs the `picker` config command), `browse.go` the builtin `@` folder browser, `pickcmd.go` `qi pick` (the builtin picker on `/dev/tty` for scripts; `ttyEditor` also serves `qi -r` before the repl exists), `filelist.go` the `@` file list for an external file picker (git files first, then a capped breadth-first walk), `external.go` the shared contract for external UI tools (`toolAvailable`, `expandTool` turns placeholders into quote-aware `$QI_*` env references so values never become shell code, `choose`, `runQuiet`, `runTTY` via `Editor.RunTTY`), `sessions.go` `/resume`, `-r`, `-show`, `render.go` renders a session as text (plain for `-show`, colored with `ui.Markdown` for the `/history` pager; a `run` call shows its code and its inner `calls`)
- `internal/llm` canonical message types, SSE, provider adapters, `retry.go` typed errors and `Retryable` (request layer retries pre-response failures, `agent.withRetries` mid-stream ones and compaction summaries, each up to 3 times with backoff; a reply cut after visible text is retried too (nothing ran yet, the partial reply was never saved) with a note that the output above is discarded; transient: 408/429/5xx, overload and rate-limit events, events whose message asks to retry, HTTP/2 resets and GOAWAY from the server, connection resets, broken pipes and timeouts; `llm.Sleep` is the injectable wait) (`openai.go` chat completions incl. OpenRouter, `responses.go` the OpenAI Responses API (stateless: `store: false`, encrypted reasoning items replayed for the same model), `anthropic.go`)
- `internal/agent` turn loop (`agent.New(Options)`, state unexported behind accessors: `mu` guards `live` (config, provider, session, system prompt, steering queue, context tokens) and is never held across I/O; the mode (`agent.Mode`: yolo, read-only, project; shift+tab cycles in that order via `Next`, a `<mode>` note tells the model on change) is an atomic; `busy` is held for a whole turn or compaction and guards `conv` (messages, the `run` tool, turn state); writers that must not land mid-turn take `busy` then `mu`), `frontmatter.go` minimal SKILL.md frontmatter parser (top-level scalars only, whitespace-normalised), `builtin.go` embedded built-in skills (`builtin/qi-config`): the skill and the schema are served from memory under `qi://skills/qi-config/` (`tools.Embed`; `read` and skill expansion check `tools.Embedded` before the disk) and listed in the static prompt, so nothing is written and the path is the same on every machine, compaction (`compact.go`: unchanged-history summary request, verbatim tail without reasoning between turns, summary-only mid-turn, overflow retry, thrash pause), steering queue, `images.go` evicts the oldest images past 100 or 24 MB (never on a normal request), system prompt (`prompt.go` records named sections for `/context`, `context.go` the breakdown), `Reset` and `Load` drop the `run` VM (`Load` tells the model when the history has `run` calls), compaction keeps it, skills, subagent runner (runs `qi -q … -json` with `QI_PARENT_SESSION` set; the child records it as `parent_session` in its meta and writes to `subagents/`, shows tool-call labels as progress, answers with the last assistant text, reports the child's final error line on failure), hooks (`hooks.go`: hook files parsed once; a missing file is skipped, an unreadable or malformed one stops startup; hooks of one event run in parallel and are waited for, except `"async": true` ones, which start detached with no output pipes and are never waited for; `async` is part of the trust fingerprint, and a command listed both ways runs blocking), project trust (`trust.go`: the trust file pins each trusted dir to a fingerprint of its project hooks)
- `internal/config` JSON config with providers and profiles (`decode.go` strict, case-sensitive decoding with encoding/json/v2 and file/key errors; `validate.go` the schema's enums, minimums and required fields; `schema.json` the embedded JSON Schema, kept in sync with the structs by a test); `mcp.go` the tool globs and the per-profile `mcp` merge by server name (null removes a global server), checked after merging; `limits.go` parses `compact_at`/`compact_idle_at` (tokens or %) and resolves them against `context_window` or a small model table
- `internal/tools` `Tool` is the one API tool, `run`; `Function` is an async JavaScript function inside it (read/write/edit/bash/jobs/subagent/tool_search/mcp, each with a `CodeSpec`); code mode (`run.go` `tools.Run(funcs...)`: a JavaScript cell in a persistent `internal/jsvm` VM; `Tool.Execute` runs the model's calls in order, parallel calls and per-path locks live inside a cell; each call through hooks (`run` itself fires none), the mode checks and the stale-file guard; `cell.go` the cell loop, its clock stops before the result is formatted, which has its own 5s bound (tests shrink both via `runner.second`, the length of one timeout second); `cellout.go` the result text; `code.go` JS arguments to tool input; `rundoc.go` the description; `Result.Calls` lands on the tool_result block as `calls`; `Tool.Reset` drops the VM, `Tool.Replace` swaps a function and regenerates the description), project mode (`project.go`: bash runs under a sandbox profile, or bwrap with `--unshare-pid`, where only the cwd, the git dir and common dir (asked from git once per session, so a redirect by the model is not followed), temp (os.TempDir and the macOS per-user temp dir, which mktemp uses), the session scratch dir, GOCACHE and GOMODCACHE (from `go env`), ~/.npm, the cargo registry, ~/.Trash and `project_writable` are writable, minus config, config.worktree, hooks, commondir and gitdir in every git dir known at session start (checked by file identity too, so case and Unicode lookalikes on APFS are caught), with each git dir, the dirs between them and `.git` pinned against rename or replace; no ptys (opening other terminals could inject input); the network stays on but on macOS unix sockets are denied except DNS, ssh-agent and sockets under the writable dirs; osascript/open/launchctl/sudo and similar are denied; signals are not limited on macOS (`(target others)` does not stop signals to unsandboxed processes); `findSandbox` probes that sandbox-exec really applies, so qi inside another sandbox reports no sandbox; `checkWritable` refuses write/edit outside those roots after resolving symlinks, dangling ones included, case-insensitively on macOS; without a usable sandbox project mode refuses bash; denials get a project-mode hint; hooks and MCP run outside the sandbox), read-only allowlist (`readonly.go`: builtins get no `$`/backtick arguments, assigning builtins are refused, go subcommands have a flag allowlist; the sandboxes also deny network), `files.go` tracks file mtimes so write refuses to overwrite a file changed since the model last read or wrote it (edit needs no guard: it only replaces exact text); it also snapshots files the model read or wrote, and the agent sends a diff of any outside change with the next tool results or user message (files without a diff, binary or too large, are listed together on one line); `image.go` scales images from read, paste and MCP to ≤1568px with a stdlib area-average resize, `read` takes `crop` for full-resolution regions; `jobs.go` background bash (`background`, timeout 1h by default, max 24h): output straight to a file in the spill dir (`.qi-out/` in the session scratch dir, a private dir also used for truncated output; nothing goes to the user cache dir), a `<background-job>` notice when the job's shell exits, times out or is killed from outside (none when qi kills it: `jobs` kill, /clear, session load, exit); processes left in its group stay listed and killable until the job's timeout, the `jobs` tool lists or kills; a job that exits while the repl waits for input starts a turn by itself once the prompt is empty (`Editor.Wake`; a timeout's notice waits for the next message), a notice that arrives mid-turn joins the next tool results; a headless run whose answer ends with jobs running gets one `<background-jobs>` note to kill what it no longer needs, then waits for the rest, and all jobs are killed on /clear, session load and exit
- `internal/ui` termios, key decoder, line editor, printer with status line (the prompt and the steering draft are multi-row `Frame`s; the printer remembers the rows it drew and clears them, recounting them after a resize reflow; a tool id `parent.N` is an inner call: it shows after its parent in the status line and its done line is indented under a dim `· <parent label>` header, the parent's own done line then shortened to its name; `ToolStartCode` (the optional `tools.SourceUI`, fed with the `run` call's code) prints a `run` call's whole code under `· run` at start when `SetRunCode(true)`, which the repl sets from `run_code` each turn), `layout.go` the pure input layout (rows with soft wrap, cursor row and column, scroll window, up/down between rows), `crash.go` (`OnCrash` cleanups, `defer ui.CleanupOnPanic()` in goroutines restores the terminal before re-panicking), `pick.go` the builtin fuzzy picker (drawn as the prompt frame via `Printer.SetPrompt`, which returns the previous prompt; `OnPick` returning a list keeps it open, `OnBack` for left), `markdown.go` streaming markdown styling of answers (TTY only; `table.go` aligns tables, `width.go` display width, `image.go` kitty graphics: after a turn the repl passes the final answer to `Printer.Images` unless `terminal_images` is false (read from the current config each turn), which draws existing image files whose paths appear in it, when `KittyGraphics` detects Ghostty/kitty outside tmux)
- `internal/session` append-only JSONL sessions (an open session file holds an exclusive flock, `lock.go`; `Tee` streams to stdout for `-json`); `Load`/`Entries` are read-only (`Open` repairs the file for appending), `List` summarizes a directory's sessions
- `internal/mcp` stdio MCP client (lazy start, tool search, per-server `tools`/`exclude_tools` globs from `config/mcp.go` enforced in the Manager: hidden tools never listed or called); exposed as `tool_search`/`mcp_call` in `internal/tools/mcp.go` (compact listing past 10 tools, never cut by the output cap), `/mcp` in `internal/app/commands.go`; subagents get the parent's `mcp` as JSON in `QI_MCP` (unset on read, replaces the config's); `mcptest` is the fake server the tests run
- `internal/proc` child processes in their own session (`proc.Session`: bash, hooks, subagents, MCP) or process group (`proc.Group`: quiet external tools, which may still need the terminal); one kill policy: SIGTERM the group, SIGKILL it after a grace period (2s, subagents 5s, MCP close 1s; tests shorten them with `SubagentRunner.Grace` and `mcp.Manager.CloseGrace`), `WaitDelay` grace plus min(grace, 1s); `Stop` escalates synchronously and `proc.Settle` waits (bounded) for escalations of cancelled commands before qi exits; TTY tools (picker, pager, `$EDITOR`) stay in the foreground group
- `internal/imgutil` the area-average `Resize`, which reads the source a row at a time so only the decoded image and the small result are held, shared by `tools/image.go` and `ui/image.go`
- `internal/testenv` shared `TestMain` (`testenv.Run`) for config, agent, app and tools: clears `QI_*`, `GIT_*`, API keys and `PAGER`, points `QI_CONFIG_DIR`/`QI_SESSION_DIR` at a temp dir; use it in new test packages

## Commands
- Build: `go build -o qi .`
- Test: `go test ./...`
- Format, vet, lint, test: `task ch` (lint runs golangci-lint v2.15.0 via `go run`, same as CI)
- Headless smoke test: `./qi -q "prompt" </dev/null` (uses `~/.config/qi/config.json`); `./qi -check-config [-config f] [-p name]` validates config without calling the API; to trigger compaction, run with `-config` pointing at a copy of the config with a small `compact_at` (e.g. `20000` or `1.5%`); the system prompt and tools alone are ~5k tokens, so lower values pause auto-compaction
- UI testing: run in tmux (`tmux new-session -d -s ai -x 120 -y 40 './qi'`, then `send-keys`/`capture-pane`); shift+tab is `$'\e[Z'`, bracketed paste via `tmux paste-buffer -p`

## Rules
- Keep the request prefix byte-stable for prompt caching: no timestamps in the system prompt, fixed tool list (read-only is enforced at execution, not by removing tools), deterministic JSON. The system prompt is two cached blocks: the static part (base prompt, global instruction files, global skills) must not depend on the directory, so every session shares it; cwd, date and project files go in the second block
- Every `tool_use` in the log needs a `tool_result`; append assistant messages only when the stream completes
- Compaction must not rewrite the history it sends (cache); messages kept after a summary carry no reasoning blocks (Claude 5.x rejects replayed thinking after a changed prefix)
- Never `MakeRaw` the terminal: it clears OPOST and output staircases; `ui.Terminal` keeps ISIG so ctrl+c is SIGINT
- No code comments
- Small, focused functions; check errors and return meaningful messages
- External UI tools (picker, pager, notifier, ...) are shell-string config keys with `{placeholders}`, never hard dependencies, documented in readme "External tools". Defaults live in `config.toolDefaults`; add new keys to `repl.toolKeys` so `/config` lists them
- Only the user's input and the model's answer print in normal color; tool lines, reasoning and info are dim
